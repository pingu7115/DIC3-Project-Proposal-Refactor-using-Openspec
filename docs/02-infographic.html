3.5Deep Research：三大核心問題對照 (38–40)
領域深探
Q1. 5 個核心思維模式 (5 Cores)：① M1 Assume Breach (查無紀錄不等於無攻擊，擴大查詢或升級 R4) ② M2 攻擊鏈脈絡 (以事件為單位多層聚合) ③ M3 錯誤成本不對稱 (漏判代價遠大於誤報，高風險實施 τ_safety 重標註) ④ M4 TTPs 優先於 IOCs (以行為技術為知識單元) ⑤ M5 可驗證的自動化 (人保留最終裁決權，防自動化自滿) (§1.1, §4 Q1)。
Q2. 3 個重要專業爭論：① 全自動 vs. 人機協作 (以 Pareto 曲線回應) ② 確定性規則 vs. 機器學習 (以硬護欄 R1–R5 與 τ_safety 融合) ③ 公開基準 vs. 真實環境 (以 GUIDE 與 ExCyTIn-Bench 雙重驗證回應) (§1.2, §4 Q2)。
Q3. 10 個深度理解問題：涵蓋 Why (Detector 誤報不關閉原因)、What-if (清除日誌反制防禦)、Trade-off (τ 門檻量化校準)、Failure Case (Living off the Land 辨識)、Comparison (TP/BP/FP 本質差異) 等 10 大關鍵技術抉擇 (§1.3, §4 Q3)。
4Proposed Scheme：系統架構與技術表示 (4.1–4.4)
八大模組架構
4.1 八大模組架構（對應規範 ①～⑧）
① User / Scenario
SOC Tier-1 分析師審閱事件佇列，執行人機裁決。
② Query / Input
接收 Incident ID、告警批次或 NL 問題，驗證格式。
③ Planner Agent
LLM ReAct 核心，動態拆解任務、調度工具與推理。
④ Data Retrieval
Evidence Store 與 SQL Log Query 跨主機/帳號取證。
⑤ Analytics Engine
LightGBM 輸出校準機率 p=(TP,BP,FP) 與 SHAP 歸因。
⑥ Domain Knowledge
Chroma 向量庫儲存 MITRE ATT&CK 與 NIST Playbook。
⑦ Decision / Fusion
加權融合、高風險規則 (R1–R5) 與主動升級判斷。
⑧ Output & UI
結構化 Markdown 事件報告，Streamlit 介面呈現。
4.2 系統流程圖（核心決策邏輯）
• 輸入 接收事件 Q → 格式驗證
• 取證 ReAct 調查迴圈 (次數 < B)
• 檢核 IsSufficient(E)? (規則防過早結案 [3])
• 分析 GBDT 輸出機率 p + SHAP 歸因
• 知識 ATT&CK 向量檢索 + LLM 脈絡推理
• 融合 Algorithm 2 加權融合 (s = w_ml·p + w_llm·q)
• 規則 高風險 R1–R5 觸發且 p_TP ≥ τ_safety → 改判 TP
• 裁決 信心不足 (conf < τ) / 衝突 / 高風險 → NEEDS_HUMAN_REVIEW
雙軌平衡：GBDT 負責百萬級快速篩選，LLM 專注複雜推理與異常質疑。
4.3 Pseudocode: Algorithm 1 (節錄附行號)
01: req ← ValidateAndParse(Q) ; if req invalid then return Error
03: plan ← Planner.Decompose(req) ; E ← ∅ ; calls ← 0
05: repeat tool ← Planner.SelectTool(plan, E) ; E ← E ∪ tool.Execute(req, E)
08:     calls ← calls + 1
09: until Planner.IsSufficient(E) or calls ≥ B   ▷ 規則防過早結案
10: x ← ExtractFeatures(E) ; p ← M.PredictProba(x) ; φ ← SHAP(M, x)
14: T ← MapToATTACK(E, KB) ; K ← KB.Retrieve(T) ∪ PB.Retrieve(T)
16: llm ← LLM.Reason(E, p, φ, S, T, K)   ▷ 回傳標籤、理由、信心
17: (label, conf, flags) ← FuseEvidence(p, llm, Rules(T))
18: if conf < τ or "conflict" ∈ flags or "high_risk" ∈ flags
    or not Planner.IsSufficient(E) then
19:     R.status ← "NEEDS_HUMAN_REVIEW"
20: else  R.status ← "AUTO_TRIAGED"
22: R.actions ← PB.Recommend(label, T) ; return R
GBDT 機率校準
ATT&CK 向量約束
安全重標註 τ_safety
終止檢核 IsSufficient
主動升級防自滿

6評估規劃與預期成效 (6.1–6.3)
嚴格防洩漏
6.1 評估設計：微軟 GUIDE (100萬真實事件) + ExCyTIn-Bench (SQL調查)。依事件、組織與時間分割，杜絕 Data Leakage。對比四大 Baseline，規劃 E1–E5 五大實驗與消融評估 (§5.4)。

• 融合架構之 TP 漏判率將顯著低於 純 GBDT 與純 LLM Baseline。
• 成功繪製 漏判率 vs. 人工升級率 Pareto 取捨曲線，驗證最適門檻 τ。
• 顯著提升 MITRE ATT&CK 技術映射正確性與事件報告可解釋性。
6.3 成果指標與實際價值：落實 M3 非對稱代價防禦；賦予分析師結構化證據鏈以防範「自動化自滿」；兼顧大規模部署之運算吞吐效率。
